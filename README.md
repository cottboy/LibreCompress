# LibreCompress

免费的纯本地 WordPress 图片压缩插件。所有处理都在服务器本地调用开源命令行工具完成，**不依赖任何第三方云服务**：无需 API Key，图片不会上传到外部服务器。

## 核心规则

插件对用户只提供一个概念：**压缩**。

一次压缩会根据当前设置，为每个文件选择以下一种处理方式：

1. **同格式压缩**：JPEG → JPEG、PNG → PNG、WebP → WebP 等。
2. **格式转换**：把勾选的 PNG、JPG、GIF 压缩为 WebP 或 AVIF。

以下入口全部共用同一套处理流程和压缩记录：

- 上传图片时自动压缩；
- 媒体库单张图片的“压缩”按钮；
- 设置页的“批量压缩未压缩的图片”按钮；
- 重试未完成的图片。

同格式压缩成功和格式转换成功都会写入同一个压缩记录表，并统一视为“已压缩”；转换后体积没有变小时保留原图，按节省 0% 记为已压缩，不会反复重试。缺工具、编码失败、文件损坏都不算完成。如果附件只有部分文件成功，媒体库会显示“部分已压缩”，批量操作只重试尚未完成的文件。绿色状态里的“已压缩%”与媒体详情页同一口径：把该附件包含的所有文件的压缩前大小和节省大小分别求和后相除，旧兼容格式回退文件一起算，原图备份不是被压缩的对象，不参与这项统计。

格式转换是真实替换：生成新文件、更新附件路径与元数据、持久改写文章内已固化的旧图片链接，新格式接管附件引用。新格式以“源文件名.webp”这类双扩展名生成。是否保留旧格式文件由“兼容格式回退”开关决定：开启时旧格式文件原地保留并同样经过压缩，作为前台 `<picture>` 的兼容格式回退；关闭时提交成功后删除源文件，磁盘上只留新格式。

## 功能特性

- **七种格式压缩**：JPEG、PNG、WebP、AVIF、GIF、SVG、JPEG XL。
- **可配置目标格式**：只有 PNG / JPG / GIF 能按设置压缩为 WebP、AVIF 或 JPEG XL；WebP / AVIF / JPEG XL 无论静图动图都只做同格式压缩，不再转换一次。
- **动图默认就压**：GIF、APNG、动画 WebP、动画 AVIF、动画 JXL 逐帧拆开压缩再重组，保留每帧播放时长、循环次数和透明通道；处理完核对帧数、总时长与透明，任一项不符就放弃并保留原文件。APNG 例外：它只走 oxipng 的无损通道（默认开启，见"APNG 自动无损压缩"）。
- **统一批量入口**：设置页的批量按钮都把任务交给服务器自己跑，按附件 ID 游标逐个处理，不存在固定数量上限。
- **后台批量任务**：任务状态存在选项里，服务器一批接一批地执行（每批限量时长，永远跑不到网关超时线），浏览器只负责显示进度，关掉页面任务照样继续；页面上的进度条是真进度，随时可停止、可只重试失败项。
- **统一状态**：媒体库、批量操作和上传自动处理使用相同的文件级成功记录。
- **全流程上传拦截**：通过 `add_attachment` 登记所有新建附件，第三方代码不生成标准 metadata 时也会在请求结束前处理；剩余待办由后台页面加载和每小时定时任务限量收尾。
- **原图备份**：压缩前可自动备份到 uploads 下的独立目录，同一附件只保留最初那份原图，SVG 同样备份；支持恢复单张或全部原图，也可设置保留天数，到期自动清理。
- **兼容格式回退**：开启后格式转换生成“源文件名.webp”“源文件名.avif”的双扩展名新文件，旧格式文件原地保留并同样经过压缩，前台用 `<picture>` 让不支持新格式的浏览器加载旧格式；回退地址由新格式名去掉最后一段扩展名确定性推导，不查询数据库。关闭后转换不再保留旧格式文件，提交成功后直接删除源文件，新格式完整替换旧格式，前台也只输出新格式。
- **隐私保护**：压缩和格式转换时默认清除 EXIF、GPS 拍摄位置、设备与软件信息，保留 ICC 色彩配置以免偏色。
- **动图保护**：识别 APNG 的 `acTL` 块、WebP 的 `ANMF` 块、AVIF/JXL 的帧计数，绝不让只认第一帧的工具把动图压成静图；APNG 只走 oxipng 的无损通道，由"APNG 自动无损压缩"控制，默认开启。
- **色彩一致性**：支持的编码器统一走 4:2:0 色度抽样；CMYK 的 JPEG 先转成 RGB 再压缩或转换，避免浏览器显示反色、编码器产出废图。
- **附件级排他锁**：同一附件的压缩、恢复和缩略图操作不会并发互相覆盖。
- **元数据同步**：格式转换后同步 `_wp_attached_file`、附件 metadata、文件大小和 MIME；原本没有完整 metadata 的图片按目标文件的真实尺寸建立，不伪造数据；主文件失败时不会把整个附件错误标记为新格式。
- **内容 URL 持久替换**：转换时把文章正文里已固化的旧地址按实际映射改写为新文件，保留查询参数、锚点、`srcset` 与区块 JSON 的转义写法；恢复时反向替换。
- **缩略图管理**：按尺寸逐个勾选是否生成，并用一个勾选框控制是否自动缩放超尺寸主图；删除未勾选尺寸时可一并清理不符设置的 `-scaled` 缩放图，补生成缺失尺寸时可一并生成或修正缩放图。
- **SVG 安全上传**：清理脚本、事件属性和危险协议，写入失败时终止上传。
- **多语言就绪**：界面文字使用翻译域 `libre-compress`。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| WordPress | 6.4 及以上 |
| PHP | 7.4 及以上 |
| `proc_open()` | 必须可用：所有压缩都以参数数组直接启动命令行工具，不经过命令行解释器（`exec()` 已不再使用） |
| PHP DOM 扩展 | 仅启用 SVG 上传时需要 |
| 压缩工具 | 按需安装，缺少对应工具时该路径会安全跳过 |

## 安装插件

1. 将 `LibreCompress` 目录上传到 `/wp-content/plugins/`。
2. 在 WordPress 后台启用插件。
3. 进入“设置 → LibreCompress”配置。
4. 在“压缩工具”页面检查本地工具状态。

## 安装压缩工具

插件不携带二进制文件，可任选一种方式：

1. 放入 `/wp-content/LibreCompress-bin/`（Windows 下通常需要 `.exe` 后缀）。
2. 将工具目录加入系统 `PATH`。
3. 使用系统包管理器安装。

### 工具清单

| 工具 | 用途 |
| --- | --- |
| jpegoptim | JPEG 同格式压缩 |
| pngquant | PNG 有损压缩 |
| oxipng | PNG 无损压缩，APNG 整只无损优化 |
| gifsicle | GIF 同格式压缩，动图帧数与每帧时长读取 |
| cwebp | WebP 同格式压缩，以及 PNG/JPG/GIF 输出为 WebP |
| gif2webp | 动画 GIF 输出为 WebP |
| img2webp | 动画 WebP 组装（动图互转时用到） |
| anim_dump | 动画 WebP 逐帧合成为整幅 PNG（libwebp 自带） |
| webpmux | 动画 WebP 帧序与每帧时长读取 |
| avifenc | AVIF 编码，含动画 AVIF 组装 |
| avifdec | AVIF 解码，含动画 AVIF 帧数读取与逐帧解码 |
| cjxl | JPEG XL 编码（同格式压缩、目标格式输出，并直接读 GIF / APNG 的逐帧时长产出动画 JXL） |
| jxlinfo | 动画 JXL 帧数与每帧时长读取 |
| ffmpeg | 动图逐帧解码为 RGBA PNG，CMYK 转 RGB |
| svgo | SVG 同格式压缩 |

libwebp 与 libjxl 的官方发行包都是压缩包形式：Windows 下把 `img2webp.exe`、`anim_dump.exe`、`webpmux.exe`，以及 `cjxl.exe`、`jxlinfo.exe` 连同 jxl 包内的 `.dll` 一起放进 `LibreCompress-bin` 即可（dll 必须和 exe 同目录）。

### 同格式压缩依赖

| 格式 | 依赖 |
| --- | --- |
| JPEG | jpegoptim |
| PNG 有损 | pngquant |
| PNG 无损 | oxipng |
| WebP | cwebp |
| AVIF | avifenc + avifdec |
| GIF | gifsicle |
| SVG | svgo |
| JPEG XL | cjxl |

PNG 严格按当前有损/无损设置选择工具，不会静默切换压缩模式。

### 格式转换依赖

| 源格式 | WebP | AVIF | JPEG XL |
| --- | --- | --- | --- |
| PNG / JPG | cwebp | avifenc | cjxl |
| 静态 GIF | GD + cwebp | GD + avifenc | GD + cjxl |
| 动画 GIF | gif2webp | ffmpeg + avifenc | cjxl |
| APNG | ffmpeg + img2webp | ffmpeg + avifenc | cjxl |

WebP、AVIF、JPEG XL 不作为转换源：它们只做同格式压缩。

### 动图处理

动图（GIF / APNG / 动画 WebP / 动画 AVIF / 动画 JXL）一律先拆成"带透明的逐帧 PNG + 每帧时长"，再按目标格式重新组装，处理完还要核对产物。

| 源格式 | 同格式压缩 | 输出 WebP | 输出 AVIF | 输出 JXL |
| --- | --- | --- | --- | --- |
| 动画 GIF | gifsicle（原生支持） | gif2webp，缺它时 ffmpeg + img2webp | ffmpeg + avifenc | cjxl |
| APNG | oxipng（需 PNG 无损模式，或开启"APNG 自动无损压缩"，默认开启） | ffmpeg + img2webp | ffmpeg + avifenc | cjxl |
| 动画 WebP | webpmux + anim_dump + img2webp | 不转换 | 不转换 | 不转换 |
| 动画 AVIF | avifdec + avifenc | 不转换 | 不转换 | 不转换 |
| 动画 JXL | cjxl | 不转换 | 不转换 | 不转换 |

WebP / AVIF / JPEG XL 无论静图动图都只做同格式压缩，不参与格式转换；APNG 与动画 GIF 是否转换，分别跟着设置里的 PNG、GIF 两个勾选走。

下面三条是实测结论，不是保守起见：

- **有损 PNG 不压 APNG**。逐帧各自调用 pngquant 会让每帧挑一张自己的调色板，动起来就是闪烁；而 APNG 规范要求所有帧共用同一张全局调色板。所以插件从不把 APNG 交给 pngquant：默认开启的"APNG 自动无损压缩"让它走 oxipng 只减体积；取消勾选且 PNG 为有损时 APNG 原样保留。
- **GIF 与 APNG 都能转动画 JXL**。cjxl 原生支持读 GIF 与 APNG 两种容器，实测自制 APNG 的 50/150/250/350 毫秒逐帧时长写进 JXL 后仍逐帧一致；其余源没有可靠的逐帧时长入口，因此不参与转换。
- **动图不输出为 GIF**。GIF 只有一位透明（要么全透明要么不透明），半透明的 AVIF/WebP 动图转回去必然丢透明；而且插件的目标格式选项本来就只有 WebP / AVIF / JPEG XL。

每次动图处理完成后会核对产物：帧数必须与原图一致、总时长误差不得超过 5%、原图有透明时产物必须有透明通道。任一项不符就整笔放弃并保留原文件——命令行工具在动画上有不少"看起来成功、实际只留第一帧"的坑（例如 ImageMagick 写出的多帧 AVIF 容器，浏览器只认第一帧），这层校验是唯一的兜底。

每帧时长内部一律按**毫秒**记录与写回（AVIF 用 1000 的时间基准，WebP 的 `-d` 本来就是毫秒，JPEG XL 由 cjxl 直接读源文件的时长）：动画 WebP 里 33 毫秒、41 毫秒这类非整十的帧时长重压后仍是 33、41，不再被抹成 30、40。GIF 自身格式只能精确到 1/100 秒，所以它转出去仍是 10 毫秒的整数倍——这是格式的天花板，不是插件丢的。

编码前还有一道对照：GIF 的透明索引（gifsicle）、APNG 的色彩类型（插件自己读 PNG 块）、动画 WebP 的透明块（webpmux）都是**独立于拆帧工具**的证据，若源声明带透明而拆出来的帧连透明通道都没有，说明这台机器的拆帧工具会丢透明，直接放弃这一张，不等编码后再靠核对兜底。实测本机的 ffmpeg 8.1.2 拆 7 种透明 GIF 形态（disposal 四种取值、gifsicle 帧间优化后的增量帧、透明索引挪到 3 号位、Imagick 带 coalesce 的构造）都是带透明通道的帧，逐帧透明像素数与 `gif2webp + anim_dump` 路线完全一致，都保住了透明；`avifenc` 的多帧序列模式也正常写 alpha 平面（透明 GIF / 透明 APNG 压出的 AVIF 逐帧解码回来透明像素与源帧一致，含"一帧透明一帧不透明"交替的序列）。动画 AVIF 不走这道对照：alpha 平面全不透明时 `avifdec` 会省掉它、输出不带透明通道的 PNG，而容器声明仍然带，硬套这条会把本来正常的动图误跳过——那种图并没丢任何透明，交给上面的产物核对即可。另外动画 WebP 的透明可以由"帧只存变化小块 + 恢复背景 + 不混合"这套播放语义表达，容器层面看不出来，所以 `webpmux` 那一列报"无透明"并不代表图不透明，这一层不做硬要求。

动图不再有帧数与尺寸上限，但命令行长度是真实天花板（Windows 约 32767 字符，Linux 是整条命令加环境变量约 2 MiB）。插件已经把这一项开销压到最低：帧文件写进系统临时目录里一个本次专用的短目录，编码器以该目录为工作目录，命令里每个帧只写裸文件名（`0.png`、`1.png`……约 8 字符）；各帧时长相同时再省一层：只给一条 `--duration`（每帧省掉约 15 个字符），时长不同才逐帧给。实测上限（按毫秒时长的命令形态重新测）：**AVIF 等时长约 3060 帧、时长不等约 1160 帧，WebP 约 1600 帧**，JPEG XL 不受影响（cjxl 直接吃 GIF/APNG 单只文件，命令里根本没有帧清单）；Linux 侧按 2 MiB 算是数万帧，等于不设限。真超限时也只是这一张按失败记录、原文件保持不动。
做不了"理论无限帧"的原因都实测过：`img2webp` / `webpmux` 的"从文件读参数列表"在 Unicode 版被禁用；`img2webp -f` 追加模式这版没有（`Unknown option [-f]`）；`webpmux -frame` 追加进已有动画会把画布撑成一列而不是加帧；换 ffmpeg 编动画 AVIF 会丢透明且逐帧时长错乱（`Alpha: Absent`、timescale 变成 12800 的乱值）。剩下的唯一办法是自己手写 AVIF/WebP 容器封装，风险与收益不成比例，插件不做。

### 色彩处理

- **4:2:0 色度抽样**：默认开启。色度抽样是"有损 YUV 格式"才有的东西，逐个格式说清楚：AVIF 能设，avifenc 对 PNG 输入默认写 4:4:4，勾选后（含动画 AVIF）走有损路径时统一加 `-y 420 --sharpyuv`，实测同一质量下照片类小 1%～2%（3456×4608 手机照片 765.3→757.5 KB，壁纸 83.1→82.2 KB），4:2:0 本身一定不比 4:4:4 大（去掉 `--sharpyuv` 更小：755.3 / 81.3 KB），变大的那一点是 `--sharpyuv`：它把色彩转得更准，纯色块类插画可能反比 4:2:0 多几百字节。WebP 有损格式**固定就是 4:2:0**，这一项对它只切换 `-sharp_yuv` 色彩转换算法。JPEG 理论上有 4:2:0/4:2:2/4:4:4 可选，但插件用的 jpegoptim 只能优化与无损重编码，**改不了抽样**，所以 JPG 保持原图的抽样方式；要强制 4:2:0 得整张重压（再多一层损失），插件不做这种事。PNG / APNG / GIF / SVG 是 RGB 或索引色，压根没有色度平面可抽。JPEG XL 的 cjxl 没开放这个参数，由它自己内部决定。产物不比原图小时，由"必须变小"的规则自动保留原图。
- **CMYK 转 RGB**：默认开启。真正会带 CMYK 的只有 JPEG（印刷排版导出常见）：读取 JPEG 的 SOF 段分量数，等于 4 即判定为 CMYK，先用 ffmpeg 转成 RGB 再交给编码器。这一步是必要的：实测 CMYK 输入会让 avifenc 与 cjxl 直接产出 0 字节文件、让 cwebp 产出几十字节的废图、让 GD 读出反色。其他格式不需要这一步——WebP/AVIF/JXL 的编码链路只接受 RGB/YUV，PNG 规范里那个 CMYK 色彩空间浏览器和工具都不支持，GIF/SVG 更是只有索引色与 RGB。转换需要 ffmpeg，缺它时该图会安全跳过。
- 选 JPEG XL 作为目标格式时建议同时开启"兼容格式回退"：浏览器对动画 JXL 的支持远不如 AVIF/WebP，保留旧格式回退才能让前台正常显示。

## 使用说明

### 基本设置

- **自动压缩**：上传图片时按当前设置自动压缩原图和全部尺寸；不生成标准 metadata 的上传会在请求结束前兜底处理。
- **备份原图**：智能备份，压缩前只把主图像（未缩放原图优先）复制一份到 uploads 下的 `libre-compress-backups/`，不再逐张备份缩略图；SVG 这类 WordPress 不写文件元数据的附件按附件登记路径取主图像。同一文件已有备份时不会覆盖，已经在映射里的格式转换结果（如 `photo.jpg.webp`）不再当作原图重复备份，备份失败时停止破坏性处理。恢复时据此写回原图，按当前勾选设置重新生成缩略图，并把正文链接还原到原来的尺寸。
- **原图备份保留时长**：单位是天，默认 `-1` 表示永久保留。填正整数则由每日定时任务删除到期备份：只删备份文件和备份索引，压缩记录与格式转换映射保留，图片仍是已压缩、已转换的状态，但从这一刻起无法再恢复原图。`0` 无效，调整步进时会自动跳过；把天数改小后，首轮任务会追溯删除所有已超期的备份。
- **兼容格式回退**：开启后格式转换生成“源文件名.webp”“源文件名.avif”的双扩展名新文件，旧格式文件原地保留并同样经过压缩，前台附件图片、文章、摘要与小工具中的转换图片用 `<picture>` 输出，支持新格式的浏览器加载新格式，不支持的浏览器加载旧格式；回退地址由新格式名去掉最后一段扩展名推导，再以磁盘上真实存在的文件为准，推导不出或文件缺失时回退自动消失。已有 `<picture>` 保持原有选择逻辑，不会重复嵌套。关闭后转换不再保留旧格式文件，提交成功后直接删除源文件，前台也只输出新格式。媒体库压缩列和设置页都提供“删除兼容格式回退”入口，用于清理此前已转换图片残留的旧格式文件；设置页的“删除所有兼容格式回退”一次清掉全部。
- **图片元数据**：“压缩时删除图片元数据”默认开启，删除 EXIF、GPS 拍摄位置、设备型号、作者与软件信息，保留 ICC 色彩配置以免偏色；取消勾选则尽量保留，各格式的实际能力见“元数据处理”。
- **SVG 上传**：允许受信任用户上传 SVG，并清理危险内容。
- **格式转换**：只有 PNG、JPG、GIF 三个勾选，勾了的源格式输出为目标格式，没勾的只做同格式压缩；动图同样按这两个勾选走（APNG 看 PNG、动画 GIF 看 GIF）。WebP、AVIF、JPEG XL 无论静图动图都不再转换一次。
- **目标格式**：WebP、AVIF、JPEG XL 三选一。
- **色彩处理**：两个勾选，分别是"支持的编码器一律使用 4:2:0 色彩抽样"和"把 CMYK 的 JPEG 转成 RGB"，默认都开启，细节见“色彩处理”。
- **自动缩放主图**：已合并进“缩略图尺寸”设置项，带一个勾选框和阈值（默认 2560，与 WordPress 默认一致）。勾选后，上传或补生成缩略图时，宽或高超过阈值的主图会另存为 `-scaled` 缩放图并接管主文件，未缩放的源文件仍留在磁盘上；不勾选则关闭自动缩放。压缩已有图片不再改动缩放，改动缩放请用“删除未勾选尺寸的缩略图”和“补生成缺失尺寸的缩略图”两个按钮：关闭缩放或缩放图与阈值不符时，删除按钮会删掉缩放图让主图退回原图；开启缩放且主图超阈值却缺少缩放图或缩放图与阈值不符时，补生成按钮会重新生成缩放图。SVG、动画 GIF、动画 WebP 与 APNG 不参与缩放。
- **缩略图尺寸**：顶部是“自动缩放主图”勾选框和阈值，下面一行一个列出当前注册的全部缩略图尺寸，默认全部勾选。取消勾选的尺寸在上传图片时不再生成，已经存在的历史文件用“删除未勾选尺寸的缩略图”清理；以后主题或插件新注册的尺寸默认勾选。APNG 不会被补生成缩略图（WordPress 图片编辑器只认第一帧）。
- **APNG 自动无损压缩**（在“压缩工具”页的 PNG 压缩里，**默认勾选**）：不管 PNG 选有损还是无损，检测到 APNG 都改用 oxipng 做无损压缩，只减体积不变画质。取消勾选后，PNG 为有损时 APNG 原样保留不压；PNG 为无损时本来就走 oxipng，与这一项无关。

### 压缩速度

速度选项位于各格式的质量设置下方，同格式压缩、静态格式转换及动画转换共用相应设置。默认使用均衡档位，兼顾服务器处理时间和体积；质量和有损 / 无损模式仍由各自设置决定。速度与最终体积的关系取决于图片内容，并非每张图片都严格单调。

| 参数 | 范围 | 方向 | 默认 |
| --- | --- | --- | --- |
| pngquant 有损 PNG 速度 | 1–11 | 越大越快 | 3 |
| oxipng 无损 PNG 级别 | 0–6 | 越大越慢 | 4 |
| cwebp 有损 WebP 方法 | 0–6 | 越大越慢 | 4 |
| cwebp 无损 WebP 级别 | 0–9 | 越大越慢 | 6 |
| gif2webp 动画 WebP 方法 | 0–6 | 越大越慢 | 4 |
| avifenc AVIF 速度 | 0–10 | 越大越快 | 6 |
| gifsicle GIF 优化级别 | 1–3 | 越大越慢 | 2 |

SVGO 另提供默认开启的“多轮优化”开关：开启时更慢、通常文件更小，关闭后仅优化一轮。jpegoptim 没有独立的速度档位。速度设置只作用于后续处理，不会自动重新压缩已完成的图片。

### 压缩结果规则

- 只有结果文件存在、可识别且体积严格小于源文件时才更换格式或替换文件内容。
- 结果没有变小：保留原图并写入 0% 的完成记录；缺工具或编码失败不写完成记录，仍保留为待处理。
- 转换结果的文件名按“源文件名.目标格式”的双扩展名规则生成，如 `photo.jpg` 转 WebP 得到 `photo.jpg.webp`；只有当这个目标名已被占用（上次转换中断的残留或同名文件）时，才先给源文件追加 `-1`、`-2` 改名再转换。源文件与目标文件主名不会互相撞名，前台的旧格式回退由新格式名去掉最后一段扩展名确定性推导，不会探到不属于本附件的图片。
- 同格式压缩和格式转换都保存当前文件路径、原始大小、压缩后大小、工具和状态。
- 压缩记录与当前文件路径不一致时视为未完成，允许重新处理。
- 附件内任意尺寸失败都不会把附件级 MIME 改成目标格式；只有主文件成功才更新附件级 MIME。
- 格式转换的提交顺序固定为：附件路径与元数据 → MIME → 文章链接。旧格式文件是否保留由兼容格式回退开关决定：开启时原地留作回退，提交不删除任何源文件；关闭时提交成功后删除源文件，新格式完整替换。任一步失败都会把引用退回源文件、把记录写成失败，下次执行凭映射继续提交而不重复编码。删除源文件只发生在引用和正文链接都已指向新格式之后，删除失败也不阻断提交，残留文件仍可由删除入口清理。
- 恢复原图先把主图像备份写回原路径并校验，再删除缩放图、缩略图与格式转换结果（绝不删到原图头上），把元数据、附件路径和 MIME 改回原图，然后按当前勾选设置重新生成缩略图（勾选了自动缩放且原图超过阈值时，`-scaled` 缩放图会重新生成并接管主文件），最后按“压缩前指向哪个尺寸就还原到哪个尺寸”的规则改写正文链接：目标文件已经重新生成好的原样还原；原来指向主图的，恢复时关闭了自动缩放就改到当前主图（也就是原图本身）；原来指向缩略图而该尺寸这次没勾选、没生成出来的，改到像素面积最接近的现有尺寸，平手选更大的；一个现有尺寸都没有时才保持原样。随后清理备份索引、压缩记录和转换映射；任一阶段失败都可重试续跑。
- 主图像备份统一在压缩这个附件之前完成（只备份主图），因此早于任何改名与转换，备份下来的是没被动过的原图；单文件处理顺序为：判断目标名是否被占用并改名 → 转换生成新格式 → 开启兼容格式回退时单独压缩旧格式。旧格式必须在转换之后再压缩，否则压缩损失会叠加到转换质量上。
- 批量操作只重试尚未成功的文件，不会再次压缩已经成功的尺寸。
- APNG 的后缀和 MIME 都是普通 PNG，只能靠 `acTL` 块识别。pngquant、cwebp、avifenc 都只读第一帧，一旦拿去压 APNG 就会把动图毁成静图，所以 APNG 只走 oxipng 的无损通道：PNG 选无损时一直压；PNG 选有损时靠默认开启的"APNG 自动无损压缩"来压，取消勾选则该图原样保留、不写记录。

### 元数据处理

“压缩时删除图片元数据”默认开启，各格式的实际行为（已按本机工具版本实测）：

| 格式 | 勾选删除（默认） | 取消勾选 |
| --- | --- | --- |
| JPEG | `jpegoptim --strip-exif --strip-iptc --strip-com`，EXIF/IPTC/注释清除，ICC 保留 | `--strip-none`，完整保留 |
| PNG | `oxipng --strip=safe` 清除 eXIf 与文本块；oxipng 会把标准 sRGB 配置换成等效的 `sRGB` 块，色彩声明不丢 | `--strip=none` 保留 eXIf；pngquant 有损路径仍会自行丢弃文本块 |
| WebP | cwebp 不写入任何元数据 | 同样不写入：该构建没有 `-metadata` 选项，保留不了 |
| AVIF | `avifenc --ignore-exif --ignore-xmp`，ICC 保留 | avifenc 默认会把输入图的 EXIF/XMP 原样带进 AVIF |
| GIF | `gifsicle --no-comments` 清除注释扩展块 | 保留注释 |
| SVG | svgo 默认预设即删除 `<metadata>` 与注释 | 同样删除，svgo 没有保留开关 |

智能备份只保存主图像（未缩放原图优先）这一份压缩前的逐字节副本，不再逐张备份缩略图，以此节省磁盘；备份只服务于“恢复原图”，恢复时会按当前设置重新生成缩略图，正文链接仍指向原来的尺寸（原来用缩略图还是缩略图，原来用原图还是原图）。目录已禁止直接访问，前台回退用的是媒体库里同样压缩过的旧格式文件，两者都不依赖备份目录对外提供图片。已经压缩过的图片改设置后不会自动重做，需要先清除对应的压缩记录。

兼容格式回退文件与压缩后的图片走同一套元数据处理：JPEG 回退由 jpegoptim 清理，PNG 回退由 oxipng/pngquant 清理，WebP 回退由 cwebp 重新编码。

### 批量操作

设置页的 7 个批量按钮全部走同一套后台任务：

- **批量压缩未压缩的图片**
- **清除压缩记录与原图备份**
- **恢复所有原图备份**
- **删除所有原图备份**
- **删除所有兼容格式回退**
- **删除未勾选尺寸的缩略图**
- **补生成缺失尺寸的缩略图**

点下按钮后只会登记一条任务，真正干活的是服务器自己：

- 服务器按附件 ID 游标一个一个处理，每批只干固定时长（默认 20 秒）就收手，把接力棒交给下一个请求，所以单个请求永远不会跑到 Nginx、宝塔、CDN 的超时线；
- 任务的类型、总数、已处理、成功 / 跳过 / 失败、失败附件 ID、游标和当前文件都写在选项 `libre_compress_task` 里，页面只是每 2 秒来看一眼，**关掉浏览器任务照样继续，重新打开设置页还能接着看进度**；
- 进度条的分母来自数据库计数或图片总数统计，所以是真的百分比，不是转圈动画；面板上另有“已处理 / 总数”“成功 / 跳过 / 失败”“当前文件”“已用时”；
- 面板上的按钮：**停止任务**（随时叫停，已处理的部分保留）、**继续执行**（接力棒掉了时手动补一棒）、**重试失败的项目**（只把失败名单里的附件重跑一遍）、**完成**（关掉结果面板，服务端会记住，刷新页面也不会再冒出来；任务还在执行时不给关，要先停止）；
- 接力棒发不出去时（个别服务器禁止网站访问自己），页面轮询会就地补一棒，另有每 2 分钟一次的定时兜底，只要站点有人访问就会接着跑；
- 失败原因按类型汇总在面板里，失败附件 ID 一并列出（最多显示前 10 个，重试最多带 200 个）。

各按钮的处理规则：

- 批量压缩：只处理仍有未压缩文件的附件，已压缩的图顺路看一眼就跳过，所有成功路径统一计入“已压缩”；
- 清除记录：连同备份文件、备份索引和转换映射一起清除，失败项会列出附件 ID，再次执行可继续清除；
- 恢复原图：备份文件已丢失又无需收尾的附件会顺手清掉残留索引；
- 删除所有原图备份：按附件逐个删除备份文件与索引；
- 删除所有兼容格式回退：删除仍有对应新格式文件的旧格式文件，并把文章里指向它们的图片链接改到新格式；
- 删除未勾选尺寸的缩略图：删掉这些尺寸的文件、清掉元数据与压缩记录，并把文章里指向它们的链接（含 srcset）改到像素面积最接近的现有尺寸（原图也一起比面积，它差得最远、排在最后），平手时选更大的；同时关闭了自动缩放或缩放图与阈值不符时，删掉 `-scaled` 缩放图让主图退回原图；
- 补生成缺失尺寸的缩略图：只为已勾选但文件缺失的尺寸生成，不重建已存在的缩略图，也不改动纯缩略图的文章链接；开启自动缩放且主图超阈值却缺少缩放图或缩放图与阈值不符时，会一并生成或修正 `-scaled` 缩放图并改写主文件链接。

## 安全与可靠性

- AJAX 接口验证 nonce、管理员权限、附件类型和附件 ID。
- 用户输入不直接提供文件路径；服务端始终根据附件 ID 和元数据重新解析文件。
- 文件路径规范化后必须位于 uploads 目录边界内。
- 备份、压缩、格式转换、恢复和缩略图操作使用附件级排他锁。
- 统一处理器生成的临时文件和回滚文件使用唯一名称。
- 压缩结果和恢复映射必须成功写入后才提交替换；元数据与映射写入都以读回结果为准，避免 WordPress 在值未变化时返回 false 被误判为失败。
- 备份索引中的路径必须落在备份目录内才会被删除，指向目录外的记录一律拒绝，防止篡改记录删掉现用图片。
- 原图备份到期清理由每日定时任务执行，到期判断在数据库内用 `NOW()` 完成（WordPress 把 PHP 时区强制设为 UTC，用 PHP 时间戳比较会让保留期偏移数小时）；同一附件的所有备份都超期才整批删除，避免恢复成一半新一半旧；单轮限量 200 个附件，仍有积压时 5 分钟后再排一次，锁被占用或索引异常的附件留到下次重试。
- 正文链接写入采用比较原内容后写入（compare-and-swap）并在失败时重读重试一次，不覆盖并发编辑。
- 附件永久删除时同步清理压缩记录、备份、转换映射、恢复中间状态和媒体库里的旧格式回退文件；旧格式文件不写进附件元数据，WordPress 不会带走它们，只能由插件按映射删除。
- 备份采用随机文件名，目录内放置 Apache、IIS 的完全拒绝访问规则和静默 index.php，任何请求都拿不到备份文件。
- SVG 清理会拒绝 DOCTYPE/ENTITY、危险元素、事件属性和脚本协议。

## 接口

自定义同格式压缩工具可继承 `Libre_Compress_Tool_Base`，实现 `get_name()`、`get_supported_formats()`、`get_executable_name()`、`build_command()` 等方法，然后通过以下钩子注册：

```php
add_action( 'libre_compress_register_tools', function ( $compressor ) {
    $compressor->register_tool( new My_Custom_Tool() );
} );
```

可用钩子：

- `libre_compress_register_tools`：注册同格式压缩工具；
- `libre_compress_before_compress`：每个文件压缩前触发；
- `libre_compress_after_compress`：每个文件压缩成功后触发。
