# LibreCompress

免费的纯本地 WordPress 图片压缩插件。所有处理都在服务器本地调用开源命令行工具完成，**不依赖任何第三方云服务**：无需 API Key，图片不会上传到外部服务器。

## 核心规则

插件对用户只提供一个概念：**压缩**。

一次压缩会根据当前设置，为每个文件选择以下一种处理方式：

1. **同格式压缩**：JPEG → JPEG、PNG → PNG、WebP → WebP 等。
2. **格式转换**：把勾选的 PNG、JPG、GIF、SVG 压缩为 WebP 或 AVIF。

以下入口全部共用同一套处理流程和压缩记录：

- 上传图片时自动压缩；
- 媒体库单张图片的“压缩”按钮；
- 设置页的“批量压缩未压缩的图片”按钮；
- 重试未完成的图片。

同格式压缩成功和格式转换成功都会写入同一个压缩记录表，并统一视为“已压缩”；转换后体积没有变小时保留原图，按节省 0% 记为已压缩，不会反复重试。缺工具、编码失败、文件损坏都不算完成。如果附件只有部分文件成功，媒体库会显示“部分已压缩”，批量操作只重试尚未完成的文件。

格式转换是真实替换：生成新文件、更新附件路径与元数据、持久改写文章内已固化的旧图片链接，新格式接管附件引用。旧格式文件按"同名不同后缀"留在媒体库原地并同样经过压缩，作为前台 `<picture>` 的兼容格式回退。

## 功能特性

- **六种格式压缩**：JPEG、PNG、WebP、AVIF、GIF、SVG。
- **可配置目标格式**：PNG / JPG / GIF / SVG 可按设置压缩为 WebP 或 AVIF；直接上传的 WebP / AVIF 始终执行同格式压缩。
- **统一批量入口**：一个按钮按当前设置处理所有未压缩图片，使用附件 ID 游标分页，不存在固定数量上限。
- **统一状态**：媒体库、批量操作和上传自动处理使用相同的文件级成功记录。
- **全流程上传拦截**：通过 `add_attachment` 登记所有新建附件，第三方代码不生成标准 metadata 时也会在请求结束前处理；剩余待办由后台页面加载和每小时定时任务限量收尾。
- **原图备份**：压缩前可自动备份到 uploads 下的独立目录，同一文件只保留最初那份原图；支持恢复单张或全部原图，也可设置保留天数，到期自动清理。
- **兼容格式回退**：格式转换后旧格式文件与新的 WebP/AVIF 同名不同后缀留在同一目录，前台用 `<picture>` 让不支持新格式的浏览器加载同样压缩过的旧格式，回退地址只靠换后缀拼接，不查询数据库。
- **隐私保护**：压缩和格式转换时默认清除 EXIF、GPS 拍摄位置、设备与软件信息，保留 ICC 色彩配置以免偏色。
- **APNG 保护**：识别 `acTL` 块，动图不参与压缩与格式转换，不会被压成静图。
- **附件级排他锁**：同一附件的压缩、恢复和缩略图操作不会并发互相覆盖。
- **元数据同步**：格式转换后同步 `_wp_attached_file`、附件 metadata、文件大小和 MIME；原本没有完整 metadata 的图片按目标文件的真实尺寸建立，不伪造数据；主文件失败时不会把整个附件错误标记为新格式。
- **内容 URL 持久替换**：转换时把文章正文里已固化的旧地址按实际映射改写为新文件，保留查询参数、锚点、`srcset` 与区块 JSON 的转义写法；恢复时反向替换。
- **缩略图管理**：按尺寸逐个勾选是否生成；可删除未勾选尺寸的旧文件并把文章链接改到最相邻的尺寸，也可只补生成缺失的尺寸。
- **SVG 安全上传**：清理脚本、事件属性和危险协议，写入失败时终止上传。
- **多语言就绪**：界面文字使用翻译域 `libre-compress`。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| WordPress | 6.4 及以上 |
| PHP | 7.4 及以上 |
| `exec()` / `proc_open()` | 必须可用，压缩依赖本地命令行工具并使用超时保护 |
| PHP DOM 扩展 | 仅启用 SVG 上传时需要 |
| 压缩工具 | 按需安装，缺少对应工具时该路径会安全跳过 |

## 安装插件

1. 将 `LibreCompress` 目录上传到 `/wp-content/plugins/`。
2. 在 WordPress 后台启用插件。
3. 进入“设置 → LibreCompress”配置。
4. 在“压缩工具”页面检查本地工具状态。

## 安装压缩工具

插件不携带二进制文件，可任选一种方式：

1. 放入 `/wp-content/LibreCompress-bin/`（Windows 下通常需要 `.exe` 后缀）。
2. 将工具目录加入系统 `PATH`。
3. 使用系统包管理器安装。

### 工具清单

| 工具 | 用途 |
| --- | --- |
| jpegoptim | JPEG 同格式压缩 |
| pngquant | PNG 有损压缩 |
| oxipng | PNG 无损压缩 |
| gifsicle | GIF 同格式压缩 |
| cwebp | WebP 同格式压缩，以及 PNG/JPG/GIF/SVG 输出为 WebP |
| gif2webp | 动画 GIF 输出为 WebP |
| avifenc | AVIF 压缩编码器 |
| avifdec | AVIF 同格式压缩所需解码器 |
| ffmpeg | 动画 GIF 输出为 AVIF |
| svgo | SVG 同格式压缩 |
| resvg | SVG 输出为 WebP/AVIF 前的栅格化处理 |

### 同格式压缩依赖

| 格式 | 依赖 |
| --- | --- |
| JPEG | jpegoptim |
| PNG 有损 | pngquant |
| PNG 无损 | oxipng |
| WebP | cwebp |
| AVIF | avifenc + avifdec |
| GIF | gifsicle |
| SVG | svgo |

PNG 严格按当前有损/无损设置选择工具，不会静默切换压缩模式。

### 格式转换依赖

| 源格式 | WebP | AVIF |
| --- | --- | --- |
| PNG / JPG | cwebp | avifenc |
| 静态 GIF | GD + cwebp | GD + avifenc |
| 动画 GIF | gif2webp | ffmpeg + avifenc |
| SVG | resvg + cwebp | resvg + avifenc |

同格式 AVIF 压缩只支持可确认的单帧文件；动画或多帧 AVIF 会安全跳过，避免静默丢帧。

动画 GIF 转换 AVIF 的无损模式使用 4:4:4 YUV 中间帧并进行无损量化编码；RGB 到 YUV 的中转仍可能产生舍入差异，不能保证与 GIF 原始 RGB 像素逐字节一致。

## 使用说明

### 基本设置

- **自动压缩**：上传图片时按当前设置自动压缩原图和全部尺寸；不生成标准 metadata 的上传会在请求结束前兜底处理。
- **压缩并发数**：批量操作使用的附件级并发数。
- **备份原图**：压缩结果提交前把原图复制到 uploads 下的 `libre-compress-backups/`；同一文件已有备份时不会用压缩结果覆盖它，备份失败时停止破坏性处理。
- **原图备份保留时长**：单位是天，默认 `-1` 表示永久保留。填正整数则由每日定时任务删除到期备份：只删备份文件和备份索引，压缩记录与格式转换映射保留，图片仍是已压缩、已转换的状态，但从这一刻起无法再恢复原图。`0` 无效，调整步进时会自动跳过；把天数改小后，首轮任务会追溯删除所有已超期的备份。
- **兼容格式回退**：格式转换后旧格式文件与新的 WebP/AVIF 同名不同后缀留在同一目录，前台附件图片、文章、摘要与小工具中的转换图片用 `<picture>` 输出，支持新格式的浏览器加载新格式，不支持新格式的浏览器加载同名的旧格式；回退地址只靠换后缀拼接，不查询数据库、不用缓存。同名不同后缀的判断以磁盘上真实存在的文件为准，因此同名文件缺失时回退自动消失。已有 `<picture>` 保持原有选择逻辑，不会重复嵌套。回退文件同样经过压缩，体积远小于原图。媒体库压缩列和设置页都提供“删除兼容格式回退”入口。可在“设置 → 兼容格式回退”整体关闭：关闭后前台只输出新格式，磁盘上的旧格式文件不受影响，仍可用删除入口清理。
- **图片元数据**：“压缩时删除图片元数据”默认开启，删除 EXIF、GPS 拍摄位置、设备型号、作者与软件信息，保留 ICC 色彩配置以免偏色；取消勾选则尽量保留，各格式的实际能力见“元数据处理”。
- **SVG 上传**：允许受信任用户上传 SVG，并清理危险内容。
- **格式转换**：勾选需要输出为 WebP/AVIF 的源格式；未勾选格式只做同格式压缩。
- **目标格式**：WebP 或 AVIF 二选一。
- **兼容格式回退**：默认开启。控制前台是否为转换后的图片包 `<picture>` 输出旧格式回退，关闭后只输出新格式；磁盘上的旧格式文件不受影响，仍可用删除入口清理。
- **大图缩放阈值**：默认 2560，与 WordPress 默认一致。上传图片的宽或高超过此阈值会重新编码出一张 `-scaled` 缩放图并接管原文件位置，未缩放的源文件仍留在磁盘上；填 0 关闭自动缩放，原图文件直接投入使用。压缩未压缩的图片时同样按此阈值处理：主文件超出就生成新的 `-scaled` 接管主文件，未缩放源文件按 WordPress 原生机制保留并写入 `original_image` 元数据，正文里固化的旧图片地址会被一并改写，已压缩的图片不再改动。SVG、动画 GIF、动画 WebP 与 APNG 不参与缩放。
- **缩略图尺寸**：一行一个列出当前注册的全部缩略图尺寸，默认全部勾选。取消勾选的尺寸在上传图片时不再生成，已经存在的历史文件用“删除未勾选尺寸的缩略图”清理；以后主题或插件新注册的尺寸默认勾选。APNG 动图不参与压缩与转换，也不会被补生成缩略图。

### 压缩速度

速度选项位于各格式的质量设置下方，同格式压缩、静态格式转换及动画转换共用相应设置。默认使用均衡档位，兼顾服务器处理时间和体积；质量和有损 / 无损模式仍由各自设置决定。速度与最终体积的关系取决于图片内容，并非每张图片都严格单调。

| 参数 | 范围 | 方向 | 默认 |
| --- | --- | --- | --- |
| pngquant 有损 PNG 速度 | 1–11 | 越大越快 | 3 |
| oxipng 无损 PNG 级别 | 0–6 | 越大越慢 | 4 |
| cwebp 有损 WebP 方法 | 0–6 | 越大越慢 | 4 |
| cwebp 无损 WebP 级别 | 0–9 | 越大越慢 | 6 |
| gif2webp 动画 WebP 方法 | 0–6 | 越大越慢 | 4 |
| avifenc AVIF 速度 | 0–10 | 越大越快 | 6 |
| gifsicle GIF 优化级别 | 1–3 | 越大越慢 | 2 |

SVGO 另提供默认开启的“多轮优化”开关：开启时更慢、通常文件更小，关闭后仅优化一轮。jpegoptim 没有独立的速度档位。速度设置只作用于后续处理，不会自动重新压缩已完成的图片。

### 压缩结果规则

- 只有结果文件存在、可识别且体积严格小于源文件时才更换格式或替换文件内容。
- 结果没有变小：保留原图并写入 0% 的完成记录；缺工具或编码失败不写完成记录，仍保留为待处理。
- 转换结果的文件名按“新旧格式同名不同后缀”规则生成；转换前扫描同目录的全部文件比主名，不管对方是什么后缀，哪怕是插件不认识的后缀，只要主名相同就先给源文件追加 `-1`、`-2` 改名，再生成新格式。WordPress 上传时只按完整文件名避让，同名不同后缀的文件完全可以共存，不查就会覆盖别人的图，或者让前台的旧格式回退探到不属于本附件的图片。
- 同格式压缩和格式转换都保存当前文件路径、原始大小、压缩后大小、工具和状态。
- 压缩记录与当前文件路径不一致时视为未完成，允许重新处理。
- 附件内任意尺寸失败都不会把附件级 MIME 改成目标格式；只有主文件成功才更新附件级 MIME。
- 格式转换的提交顺序固定为：附件路径与元数据 → MIME → 文章链接；旧格式文件留在原地作为兼容格式回退，提交不删除任何源文件。任一步失败都会把引用退回源文件、把记录写成失败，下次执行凭映射继续提交而不重复编码。
- 恢复原图先写回备份并校验内容，再改回引用与文章链接，最后才删除转换结果、备份索引和压缩记录；原路径被其他图片占用时直接拒绝，不覆盖。旧格式回退文件已在磁盘上时同样允许备份覆盖它——那是本次要退回的源文件。
- 单文件处理的顺序固定为：判断同名冲突并改名 → 备份原图 → 转换生成新格式 → 单独压缩旧格式。备份必须早于改名和转换，否则备份下来的是动过的文件；旧格式必须在转换之后再压缩，否则压缩损失会叠加到转换质量上。
- 批量操作只重试尚未成功的文件，不会再次压缩已经成功的尺寸。
- APNG 动图整体跳过：不压缩、不转换、不写记录，媒体库仍显示未压缩。它的后缀和 MIME 都是普通 PNG，只能靠 `acTL` 块识别，而 pngquant、cwebp、avifenc 都只读第一帧，一旦处理就会把动图毁成静图。

### 元数据处理

“压缩时删除图片元数据”默认开启，各格式的实际行为（已按本机工具版本实测）：

| 格式 | 勾选删除（默认） | 取消勾选 |
| --- | --- | --- |
| JPEG | `jpegoptim --strip-exif --strip-iptc --strip-com`，EXIF/IPTC/注释清除，ICC 保留 | `--strip-none`，完整保留 |
| PNG | `oxipng --strip=safe` 清除 eXIf 与文本块；oxipng 会把标准 sRGB 配置换成等效的 `sRGB` 块，色彩声明不丢 | `--strip=none` 保留 eXIf；pngquant 有损路径仍会自行丢弃文本块 |
| WebP | cwebp 不写入任何元数据 | 同样不写入：该构建没有 `-metadata` 选项，保留不了 |
| AVIF | `avifenc --ignore-exif --ignore-xmp`，ICC 保留 | avifenc 默认会把输入图的 EXIF/XMP 原样带进 AVIF |
| GIF | `gifsicle --no-comments` 清除注释扩展块 | 保留注释 |
| SVG | svgo 默认预设即删除 `<metadata>` 与注释 | 同样删除，svgo 没有保留开关 |

原图备份是压缩和转换前那份文件的逐字节副本，不再单独做元数据处理：备份只服务于“恢复原图”，目录已禁止直接访问，前台回退用的是媒体库里同样压缩过的同名旧格式文件，两者都不依赖备份目录对外提供图片。已经压缩过的图片改设置后不会自动重做，需要先清除对应的压缩记录。

兼容格式回退文件与压缩后的图片走同一套元数据处理：JPEG 回退由 jpegoptim 清理，PNG 回退由 oxipng/pngquant 清理，SVG 回退由 svgo 清理，WebP 回退由 cwebp 重新编码。

### 批量操作

设置页提供一个批量入口：

- **批量压缩未压缩的图片**

该按钮按附件 ID 游标逐页读取媒体库，并使用设置中的并发数处理。所有成功路径统一计入“已压缩”。

设置页还提供：

- 清除压缩记录与原图备份：每请求 20 个附件的游标分页，连同备份文件、备份索引和转换映射一起清除，失败项会列出附件 ID，再次执行可继续清除；
- 恢复所有原图备份：每请求 20 个附件的游标分页，失败项会列出附件 ID，再次执行可继续恢复；
- 删除所有原图备份；
- 删除所有兼容格式回退：每请求 20 个附件的游标分页，删除仍有对应新格式文件的旧格式文件，并把文章里指向它们的图片链接改到新格式，失败项会列出附件 ID，再次执行可继续删除；
- 删除未勾选尺寸的缩略图：删掉这些尺寸的文件、清掉元数据与压缩记录，并把文章里指向它们的链接（含 srcset）改到像素面积最接近的保留尺寸，平手时选更大的，没有保留尺寸时兜底用原图；
- 补生成缺失尺寸的缩略图：只为已勾选但文件缺失的尺寸生成，不重建已存在的文件，也不改动任何文章链接。

## 安全与可靠性

- AJAX 接口验证 nonce、管理员权限、附件类型和附件 ID。
- 用户输入不直接提供文件路径；服务端始终根据附件 ID 和元数据重新解析文件。
- 文件路径规范化后必须位于 uploads 目录边界内。
- 备份、压缩、格式转换、恢复和缩略图操作使用附件级排他锁。
- 统一处理器生成的临时文件和回滚文件使用唯一名称。
- 压缩结果和恢复映射必须成功写入后才提交替换；元数据与映射写入都以读回结果为准，避免 WordPress 在值未变化时返回 false 被误判为失败。
- 备份索引中的路径必须落在备份目录内才会被删除，指向目录外的记录一律拒绝，防止篡改记录删掉现用图片。
- 原图备份到期清理由每日定时任务执行，到期判断在数据库内用 `NOW()` 完成（WordPress 把 PHP 时区强制设为 UTC，用 PHP 时间戳比较会让保留期偏移数小时）；同一附件的所有备份都超期才整批删除，避免恢复成一半新一半旧；单轮限量 200 个附件，仍有积压时 5 分钟后再排一次，锁被占用或索引异常的附件留到下次重试。
- 正文链接写入采用比较原内容后写入（compare-and-swap）并在失败时重读重试一次，不覆盖并发编辑。
- 附件永久删除时同步清理压缩记录、备份、转换映射、恢复中间状态和媒体库里的旧格式回退文件；旧格式文件不写进附件元数据，WordPress 不会带走它们，只能由插件按映射删除。
- 备份采用随机文件名，目录内放置 Apache、IIS 的完全拒绝访问规则和静默 index.php，任何请求都拿不到备份文件。
- SVG 清理会拒绝 DOCTYPE/ENTITY、危险元素、事件属性和脚本协议。

## 数据存储

| 数据 | 位置 |
| --- | --- |
| 统一压缩记录 | `{表前缀}libre_compress_records` |
| 备份记录 | `{表前缀}libre_compress_backups` |
| 格式转换恢复映射 | 附件 post meta `_libre_compress_output` |
| 恢复收尾状态 | 附件 post meta `_libre_compress_restore_ready` |
| 上传待处理标记 | 附件 post meta `_libre_compress_pending` |
| 原图备份文件 | `/wp-content/uploads/libre-compress-backups/` |
| 兼容格式回退文件 | 与新格式文件同目录同名，仅后缀不同，如 `example.jpg` 与 `example.webp` |
| 备份到期清理任务 | 定时任务 `libre_compress_backup_prune_event`，每天一次 |
| 本地工具 | `/wp-content/LibreCompress-bin/` |
| 附件处理锁 | `/wp-content/uploads/.libre-compress-locks/` |

## 开发者接口

自定义同格式压缩工具可继承 `Libre_Compress_Tool_Base`，实现 `get_name()`、`get_supported_formats()`、`get_executable_name()`、`build_command()` 等方法，然后通过以下钩子注册：

```php
add_action( 'libre_compress_register_tools', function ( $compressor ) {
    $compressor->register_tool( new My_Custom_Tool() );
} );
```

可用钩子：

- `libre_compress_register_tools`：注册同格式压缩工具；
- `libre_compress_before_compress`：每个文件压缩前触发；
- `libre_compress_after_compress`：每个文件压缩成功后触发。
